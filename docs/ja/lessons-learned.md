# ここまでで学んだこと

> 本プロジェクトの検証過程で得られた技術的知見をまとめています。

## 2段階 AI 分析でコスト 85% 削減

全画像を高精度モデル (Claude Sonnet) で分析すると月額 ~$259。Haiku でスクリーニングし異常疑いのみ Sonnet に回す 2段階構成で月額 ~$40 に削減できました。

**設計パターン:**

```
画像到着 → Haiku (安価・高速) → 正常: 終了
                              → 異常疑い: Sonnet (高精度) → 判定結果
```

- Haiku: $0.25/1M input tokens — 全量処理に適する
- Sonnet: $3.00/1M input tokens — 精査が必要な画像のみ
- 異常率 5% 想定で ~85% コスト削減

このパターンは画像判定以外の AI パイプライン（テキスト分類、音声分析等）にも応用可能です。

## プロンプトだけで産業用画像判定が実用精度に達する

カスタムモデル学習なしで、Claude Vision のプロンプトのみで 3D プリント欠陥を 9/9 正解しました。

**テスト条件:**
- 公開画像 + 合成画像を使用
- 欠陥タイプ: 層間剥離、ストリンギング、反り、ノズル詰まり
- プロンプトに判定基準を明示的に記述

**注意点:**
- 実環境（照明条件、カメラ角度、フィラメント色の違い）での精度は未検証
- 本番適用にはドメイン固有のプロンプトチューニングと閾値調整が必要

## FSx for ONTAP S3 Access Points の制約

S3 Access Points (2025年 GA) により、ONTAP に集約したデータへ S3 API でアクセスできるようになりました。ただし以下の制約があります:

| 制約 | 影響 | 対策 |
|------|------|------|
| 条件付き書き込み非対応 | Iceberg/Delta Lake の直接書き込み不可 | FPolicy + Lambda で補完 |
| イベント通知非対応 | S3 Event Notifications が使えない | FPolicy でファイル到着検知 |
| AD 参加 SVM では AD DC 到達性が必須 | DC 不通時に全データ操作が AccessDenied | 事前ヘルスチェックを組み込む |

詳細: [FAQ](faq.md)

## ONTAP REST API は IoT テレメトリ収集に十分使える

パフォーマンスメトリクス、容量、健全性を 1 分間隔で収集可能です。

- ポーリングベースだが PoC には十分な粒度
- `/api/cluster/metrics` でクラスタ全体、`/api/storage/volumes` でボリューム単位
- 認証は ONTAP ローカルアカウント or AD 統合

**制約:**
- Push 型（Webhook）はなし。ポーリング間隔の設計が必要
- 大量ボリューム環境ではページネーション処理が必要
