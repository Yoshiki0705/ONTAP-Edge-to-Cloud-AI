# デプロイメントモデル

> 最終確認: 2026-08-19

同じパターンを、どの規模・どの業種で使うかによって構成が変わります。その差分を扱います。

[パターンカタログ](../aws-patterns/README.md) が「何を作るか」なら、こちらは
「どこに、どういう規模で置くか」です。

## 収録しているモデル

| モデル | 対象 | 詳しさ |
|---|---|---|
| [Model A: 単一工場](model-a-single-factory.md) | 1 拠点、数台〜数十台のデバイス | データフロー / ストレージ / AI / セキュリティ統制 / コストの考え方 |
| [Model B: 複数工場](model-b-multi-factory.md) | 複数拠点、拠点間のデータ集約 | 同上 |
| [Model C〜F: 他業種での差分](model-c-f-other-industries.md) | 小売 / 医療 / 通信 / エネルギー | A・B との差分のみ |

## 詳しさが違う理由

**A と B は詳述し、C〜F は差分に絞っています。** このリポジトリの実装と検証は
製造業のユースケース（[3D プリント品質監視](../../../usecases/3d-print-quality/)、
[外観検査](../../../usecases/visual-inspection/)）を対象にしており、
他業種については実装も測定も業種固有の一次情報もありません。

4 業種を等しく詳述すると、書ける材料がないまま分量を揃えることになります。
それは公開リファレンスとして避けたい形です。C〜F では
「A・B と比べて何が変わるか」（規制要件、データ所在、レイテンシ要求、コスト構造）に
絞り、未実装であることを明記しています。

## 選び方

| 状況 | 見るモデル |
|---|---|
| 1 拠点で始める | [A](model-a-single-factory.md) |
| 拠点が複数あり、横断で見たい | [B](model-b-multi-factory.md) |
| 拠点は 1 つだが、将来増える | [A](model-a-single-factory.md) を読んだ後 [B](model-b-multi-factory.md) の「A から B へ移るとき」を読む |
| 製造以外の業種 | [C〜F](model-c-f-other-industries.md) で差分を確認し、A か B に戻る |

**A から B への移行で最も高くつくのは、拠点を識別する仕組みを後から入れることです。**
1 拠点で始める場合も、イベントスキーマとストレージのパスに拠点の識別子を
最初から入れておくと、移行時の書き換えが減ります。

## 横断する前提

- **パターンの選択は別**: どの AI 経路を使うかは [パターンカタログ](../aws-patterns/README.md)
- **セキュリティ統制の詳細**: [セキュリティ設計](../security-design.md)。
  各モデルでは「そのモデルで何が変わるか」だけを書きます
- **金額**: [デプロイガイド](../deployment-guide.md)。各モデルには費用を駆動する要素のみ
- **実測値ではありません**: このリポジトリは実機テストが未完了です
  （[README](../../../README.md#このリポジトリについて)）。性能・コストの数値は書きません

## 未実装の項目

| 項目 | 影響するモデル |
|---|---|
| 複数拠点での実運用 | B |
| 拠点をまたぐデータ同期の検証 | B |
| 業種固有の規制要件への適合評価 | C〜F |
| 大規模デバイス群のプロビジョニング | A, B |
