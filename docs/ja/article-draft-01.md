## TL;DR

工場や拠点の IoT デバイスが生成するデータは、デバイスごと・拠点ごとに分散しがちです。この記事では、ONTAP にデータを集約し、Kafka + ClickHouse でリアルタイム分析、AWS Bedrock で画像 AI 判定を行うハイブリッドパイプラインの設計を共有します。最初の検証対象は「3Dプリント品質監視」です。

## 1. 解決したい課題

現場を訪問すると、こんな状況をよく見かけます:

- カメラの画像はプリンター内蔵クラウドに
- センサーデータは Raspberry Pi の SD カードに
- 設備ログは Windows PC にバラバラに

データは生成されているのに、**横断的に分析する手段がない**。さらにオンプレ側には分析基盤やガバナンスツールがなく、「ツールを作るところから始める必要がある」のが着手の障壁になっていました。

## 2. アプローチ: 集約 → リアルタイム分析 → AI

3層のハイブリッド構成にしました。

```
[エッジ]          [データハブ]        [リアルタイム]      [AI/分析]
Raspberry Pi  →   ONTAP (NFS)     →   Kafka           →  AWS Bedrock
カメラ/センサー    画像/CSV保存         ClickHouse         Athena/Glue
              →   Kafka (event)        ダッシュボード      Databricks
```

**設計の肝は「ペイロードとイベントの分離」です。**

- **ペイロード**（画像、CSV など大容量）: エッジ → NFS → ONTAP に保存
- **イベント**（メタデータ: いつ、どこで、何を）: エッジ → Kafka → ClickHouse

大容量バイナリは ONTAP に置き、軽量なメタデータだけを Kafka に流すことで、リアルタイム分析を高速に保ちつつ、原本データはローカルに蓄積されます。

## 3. なぜこの構成なのか

### ONTAP をデータハブにする理由
- NFS / SMB / S3 を同一データで提供（マルチプロトコル）
- 既存の NAS ワークフローをそのまま活かせる
- S3 Access Points 経由で AWS から直接アクセス（データコピー不要）

ただし **ONTAP がなくても核となるパターンは成立します**。S3 直接や EFS でも実現可能で、記事の後半で比較します。

### Kafka + ClickHouse をオンプレに置く理由
- エッジ（Pi）と同じ LAN 上に置くことで低遅延
- ClickHouse はリアルタイム分析エンジンとして高速（カラムナー）
- 工場のネットワークがクラウドと切れても、ローカルで分析が続く

### AI をクラウド（Bedrock）にする理由
- ローカル GPU 不要、従量課金
- Claude Vision のプロンプトのみで産業用画像判定が実用精度に到達（カスタムモデル学習不要）

## 4. 学んだこと（検証段階）

### 2段階 AI 分析でコスト 85% 削減
全画像を高精度モデル（Claude Sonnet）で分析すると月 $259。Haiku でスクリーニングし、異常疑いのみ Sonnet に回すと月 $40 に。この設計パターンは他の AI パイプラインにも応用できます。

### 切断耐性は「ローカルが真実」で設計する
工場のネットワークは不安定です。そこで:
- ONTAP への保存は Kafka の状態に依存しない（NFS はローカル LAN）
- Kafka 断時はローカルバッファに JSON 保存 → 復旧後に時系列順リプレイ
- event_id による冪等性で、リプレイ時の重複を排除

### スキーマを最初に統一する価値
エッジ → Kafka → ClickHouse → Databricks と流れるイベントのスキーマを、最初に統一エンベロープ（event_id, site_id, equipment_id, payload_uri, ...）として定義しました。これにより、4つの異なるシステムが型レベルで整合し、後からの手戻りがありません。

## 5. ストレージ選択肢の比較

ONTAP を前提にしていますが、課題（集約 → 分析）は他でも解けます。

| ストレージ | 特徴 | 制約 |
|-----------|------|------|
| S3 直接 | 最もシンプル、AWS ネイティブ | NFS/SMB 不可 |
| EFS | NFS マウント可、Linux 親和 | SMB 不可、S3 API 直接不可 |
| ONTAP | NFS+SMB+S3 同一データ、FPolicy、SnapMirror、ARP/AI | ONTAP 環境が必要 |

**選び方**: 新規構築なら S3、NFS で書きたいなら EFS、既存 NAS があり NFS+SMB 両方必要なら ONTAP。
