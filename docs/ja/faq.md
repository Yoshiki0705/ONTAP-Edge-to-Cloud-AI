# FAQ: Edge-to-Cloud AI

> パートナー/SI が顧客から受ける典型的な質問と回答

---

## セキュリティ

**Q: デバイスがハッキングされたらどうなりますか？**

A: 3層の防御を設計しています。(1) デバイスに AWS 認証情報を保存しない（SORACOM SIM 認証 + AssumeRole）、(2) ネットワークセグメンテーション（ONTAP 管理プレーンへのアクセス不可）、(3) ONTAP ARP/AI が異常な書き込みパターンを検知し自動 Snapshot で保護。デバイス侵害時は SIM 停止で即座に通信を遮断できます。

**Q: 画像データはどこに保存されますか？暗号化されていますか？**

A: S3（SSE-KMS 暗号化）と ONTAP（NVE: AES-256）に保存されます。転送中も TLS 1.2+ で暗号化。S3 バケットポリシーで非暗号化通信を拒否しています。

**Q: カメラ画像に従業員が映り込む可能性は？**

A: カメラは製品/設備のみを撮影する位置に設置します。人が映り込む可能性がある場合は、設置前にプライバシー影響評価を実施し、必要に応じて撮影範囲の制限、ぼかし処理、または設置場所の変更で対応します。

## コスト

**Q: 月額いくらかかりますか？**

A: PoC 規模（1デバイス）で約 ¥5,500/月（AWS ~¥5,000 + SORACOM ~¥500）。2段階AI分析により、全画像を高精度モデルで分析する場合の約 85% のコスト削減を実現しています。

**Q: 本番展開するとコストはどうなりますか？**

A: デバイス数に比例します。10台展開の場合: AWS ~¥30,000-50,000/月 + SORACOM ~¥5,000/月 + ハードウェア初期費 ~¥150,000。ただし、正常時は安価な Haiku モデルのみ使用するため、異常率が低いほどコスト効率が良くなります。

**Q: 既存の AWS 環境に追加コストなく統合できますか？**

A: 既存の S3、CloudWatch、IAM を活用できます。追加コストは Bedrock API 呼び出し（従量課金）と Kinesis（ON_DEMAND: データ量に応じた課金）のみです。

## 技術

**Q: 既存の ONTAP / NAS 環境がなくても使えますか？**

A: はい。ONTAP 連携は Phase 2 のオプションです。Phase 1 は Pi + SORACOM + S3 + Bedrock のみで動作します。ONTAP がある場合は、既存データの AI 活用やイベント駆動連携で追加価値を提供します。

**Q: インターネット接続がない現場でも使えますか？**

A: SORACOM セルラー SIM により、有線ネットワークがない現場でも動作します。ただし、セルラー圏外の場合はローカルバッファに蓄積し、通信復旧後に一括送信します。完全オフライン環境では、エッジ推論（TensorFlow Lite）による簡易判定が可能です（Phase 3 以降）。

**Q: AI の精度はどのくらいですか？**

A: テスト段階で 100%（9/9 テストケース正解）。実運用では環境条件（照明、カメラ位置、フィラメント色）により変動するため、PoC で実環境精度を検証します。目標は精度 80% 以上、誤検知率 10% 以下です。

**Q: 対応できる検査対象は 3D プリントだけですか？**

A: いいえ。アーキテクチャは汎用的です。プロンプトを変更するだけで、外観検査（傷、変色、寸法）、在庫管理（棚卸し）、安全装備確認（ヘルメット着用）など、任意の画像判定に適用できます。

**Q: Raspberry Pi は産業用途に耐えますか？**

A: PoC/パイロットでは十分です。本番展開では、産業用エンクロージャ（防塵/防水）、UPS（停電対策）、産業用 Pi 互換機（RevPi 等）の検討を推奨します。

## 運用

**Q: デバイスが故障したらどうなりますか？**

A: (1) 5分間キャプチャがないと自動アラート、(2) SORACOM Napter で遠隔診断、(3) 復旧不可の場合は予備機に交換（セットアップ手順書あり、所要30分）。印刷自体は Pi なしでも継続可能です。

**Q: AI が誤検知した場合の影響は？**

A: severity: high/critical の場合のみ自動停止（再開可能）。それ以外は通知のみで人間が判断します。誤検知によるフィードバックを記録し、週次で精度改善に反映します。

**Q: 既存の監視システム（Nagios、Zabbix 等）と統合できますか？**

A: SNS 経由で任意のエンドポイントに通知可能です。Webhook、メール、SMS、PagerDuty、Slack に対応。CloudWatch メトリクスを既存監視に取り込むことも可能です。

## 導入プロセス

**Q: PoC にどのくらいの期間がかかりますか？**

A: 4週間（環境準備1週 + 構築1週 + 検証運転1週 + 評価1週）。AWS インフラは CloudFormation で 1コマンドデプロイ、エッジデバイスはセットアップ手順書に従い 1-2 時間で稼働開始できます。

**Q: PoC 後に本番化する場合、何が変わりますか？**

A: 主な追加項目: (1) デバイス台数の増加、(2) 24/7 監視体制、(3) OTA 更新の自動化、(4) セキュリティ強化（VPG 閉域網）、(5) SLA/SLO の正式合意。アーキテクチャ自体は PoC と同一です。

**Q: AWS の知識がない現場担当者でも運用できますか？**

A: 日常運用は Slack/Teams の通知確認とフィードバック記録のみです。AWS コンソール操作は不要。障害時は Runbook に従って対応し、解決しない場合はエスカレーションフローで技術者に引き継ぎます。
